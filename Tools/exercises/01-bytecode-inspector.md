# 第一题：实现字节码检查工具

在 `test/1d5735e8462` 分支完成。共同交付要求和评审标准见 [README](README.md)。本题现在可以开始。

## 目标与接口

新增 `Tools/byteinspect.py`，允许使用宿主机 Python 3 编写，仅使用标准库。

训练重点：当前版本的指令编码、指令边界、表下标和跳转目标验证。

调用接口：

```sh
python3 Tools/byteinspect.py \
    --hex "64 00 00 53" \
    --const-count 1 \
    --name-count 0 \
    --local-count 0
```

上面的输入按十六进制解释，对应 `LOAD_CONST 0` 和 `RETURN_VALUE`。

输出每条指令的字节偏移、名称和参数。跳转指令还要输出计算后的目标偏移。

## 验收要求

1. 正确区分一字节和三字节指令，参数按低字节在前读取。
2. 指令名称和编号以当前 `Include/opcode.h` 为依据，不能照搬现代 Python 的 `dis`。
3. 拒绝未知 opcode、非法输入字节和被截断的参数。
4. 检查常量表、名字表、局部槽位下标是否越界。
5. 正确区分相对跳转和绝对跳转。
6. 跳转目标必须位于代码范围内，并落在指令起点，不能落在参数字节里。
7. 合法输入退出码为零；错误输入返回非零，并指出出错偏移和原因。
8. 检查失败不能出现未处理的 Python traceback。

## 必须调查的细节

- 有些合法指令编号通过范围表示，并不是每个编号都有独立的 `#define`。
- `RESERVE_FAST` 的参数究竟索引什么？不要仅依赖 opcode 的注释。

## 测试要求

至少覆盖：

| 情况 | 要求 |
| --- | --- |
| 参数超过 255 | 正确解码 |
| 相对与绝对跳转 | 正确计算目标 |
| 跳入参数字节 | 拒绝 |
| 跳出代码范围 | 拒绝 |
| 三字节指令只剩一两个字节 | 拒绝 |
| 三类表下标越界 | 分别拒绝 |
| 合法但没有单独宏定义的指令 | 正确识别 |
| 当前解释器生成的真实函数字节码 | 能解码和检查 |

真实函数样本必须包含算术、`if`、循环和函数调用。样本必须来自当前解释器，不能来自宿主机 Python 3 的字节码。

设计说明必须界定工具能证明什么、不能证明什么。例如，指令边界合法是否足以保证执行安全？
