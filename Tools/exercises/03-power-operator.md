# 第三题：实现 `**` 幂运算符

在 `test/1d5735e8462` 分支完成。共同交付要求和评审标准见 [README](README.md)。第二题通过评审后再开始。

## 目标

当前解释器没有 `**` 运算符（`2 ** 3` 是语法错误），但数字协议里已经有 `nb_power`
槽（见 `Objects/intobject.c`、`Objects/floatobject.c`、`Objects/longobject.c`）。
端到端实现一个 `**` 二元运算符。

训练重点：词法分析、语法产生式与优先级/结合性、AST 到字节码的生成、新增 opcode、
数字协议与强制转换、错误传播。

## 涉及层次

- `Parser/tokenizer.c`：识别 `**`（当前 `*` 一律产生 `STAR`）。
- `Grammar/Grammar`：新增产生式，处理优先级与结合性。
- `Include/opcode.h`：新增无参数的 `BINARY_POWER`。
- `Python/compile.c`：为 `**` 生成新指令。
- `Python/ceval.c`：新增 `case BINARY_POWER`，通过 `nb_power(v, w, None)` 求值。
- 用 pgen 重新生成 `Python/graminit.c`、`Include/graminit.h`。

## 语义规定

- 优先级：`**` 高于其左侧的一元 `+ - ~`，右侧允许一元运算符。即：
  `-2 ** 2 == -4`，`2 ** -1` 合法。
- 结合性：右结合。`2 ** 3 ** 2 == 2 ** (3 ** 2) == 512`。
- 支持 int、float、long，以及实现了 `nb_power` 的对象。
- 混合类型按现有 coerce 规则处理。
- 负数次幂、整数溢出、除零等错误，沿用数字协议现有的异常类型与行为。
- 不得改变其它运算符的优先级或结合性。

## 实现约束

- 必须从 `Grammar/Grammar` 源文件重新生成语法表，不能只改生成表。
- 复用现有数字协议，不要在 `ceval.c` 里直接针对 int/float 特判。
- 新 opcode 的编号选择要合理，并说明它对既有指令编码（一字节/三字节）的影响。

## 验收要求

1. `2 ** 3`、`2.0 ** 3`、`2 ** 3.0` 结果正确。
2. 优先级与结合性：`-2 ** 2`、`2 ** -1`、`2 ** 3 ** 2`、`2 * 3 ** 2` 全部符合规定。
3. 错误路径：负整数次幂、溢出等按现有协议报错，不被替换。
4. 未知运算符组合不受影响（`*`、`/`、`%`、移位等行为不变）。
5. 从语法源重新生成并构建后行为一致。

## 测试要求

必须覆盖：

| 情况 | 要求 |
| --- | --- |
| int/int、float、混合 | 结果正确 |
| `-2 ** 2` / `2 ** -1` / `2 ** 3 ** 2` | 优先级、结合性正确 |
| `**` 与 `*`、`/`、`%`、移位混用 | 优先级正确 |
| 负整数次幂 / 溢出 | 正确异常 |
| 语法边界 | `**`、`**=`、越界组合等按你的定义处理并测试 |
| 重新生成语法表 | 从源重建后行为不变 |

测试必须有自动判定与非零失败退出状态。
