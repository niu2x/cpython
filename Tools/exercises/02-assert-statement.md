# 第二题：添加 assert 语句

在 `test/1d5735e8462` 分支完成。共同交付要求和评审标准见 [README](README.md)。第一题通过评审后再开始。

## 目标

当前语法没有 `assert`。新增以下两种语句：

```python
assert condition
assert condition, message
```

训练重点：语法扩展、静态语义处理、字节码生成、短路行为、引用所有权和异常传播。

## 语义规定

- `condition` 恰好求值一次。
- 条件为真时，不求值 `message`。
- 条件为假时，求值消息并抛出 `AssertionError`。
- 条件或消息求值本身抛异常时，传播原异常。
- 使用当前版本的字符串异常机制。
- 本题中 `assert` 始终生效，不添加优化开关。
- `AssertionError` 按普通名字查找规则解析，允许被用户重新绑定。

## 实现约束

- 使用现有字节码完成，不添加新 opcode。
- 通过 `pgen` 生成语法表，不能直接手改生成表作为实现。
- 改动必须能从语法源文件重新生成并构建。
- 不混入无关的历史源码修复。

## 测试要求

必须覆盖：

- 条件成立与不成立，两种语句形式。
- 条件表达式只求值一次的副作用检查。
- 条件成立时消息表达式完全不求值。
- 条件或消息表达式自身抛异常，原异常不被替换。
- 用户重新绑定 `AssertionError` 后的行为。
- 嵌套函数中的使用。
- `try/except` 与 `try/finally` 中的行为。
- 非法语法。
- 一次失败被处理后，解释器仍能继续执行代码。

测试必须有自动判定与非零失败退出状态，不能只检查打印输出是否“看起来正确”。
