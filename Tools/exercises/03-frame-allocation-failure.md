# 第三题：修复并验证 frame 分配失败路径

在 `test/1d5735e8462` 分支完成。共同交付要求和评审标准见 [README](README.md)。第二题通过评审后再开始。

## 目标

检查 `newframeobject()` 的分配与初始化过程，找出内存不足时可能发生的问题并修复。

训练重点：部分初始化对象、错误路径、引用计数、空闲对象复用和执行状态恢复。

## 验收要求

- 分配失败返回 `NULL`，设置正确的异常。
- 不访问空指针。
- 不泄漏已经取得的引用。
- 不破坏 frame 空闲链表。
- 不破坏调用者的 `current_frame`。
- 失败之后，后续正常执行仍然可用。

## 失败注入要求

必须提供确定性的失败注入测试，不能靠“申请大量内存试试看”。

失败注入应局限于测试需要，正常构建不能改变行为。必须解释注入位置、触发条件，以及如何证明测试确实走到了目标失败分支。

## 测试要求

分别验证：

1. 新 frame 分配路径。
2. 空闲 frame 复用路径，包括需要分配或扩展栈缓冲区的情况。

测试不仅要证明“不崩溃”，还要检查异常状态、引用清理、调用者现场与后续执行。

先记录未修复版本在目标失败路径下的行为，再证明补丁改变了该行为。

## 设计说明与评审追问

提交时必须：

1. 列出 frame 初始化中的分配点和引用取得点。
2. 说明每个失败位置已经初始化了哪些字段，哪些字段仍不可使用。
3. 解释清理为何不会读取未初始化字段、重复释放引用或损坏空闲链表。
4. 解释 `current_frame` 在创建失败与创建成功后的退出路径中如何保持正确。
5. 说明测试如何区分新分配与复用路径，并验证失败后还能正常执行。
