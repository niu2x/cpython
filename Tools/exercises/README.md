# 早期 CPython 开发训练

目标：通过独立实现、测试、评审和修改，训练解释器开发能力，为参与现代 CPython 开发建立基础。

训练分支：`test/1d5735e8462`。它基于 1994 年的提交 `1d5735e8462`，包含适配当前编译环境的修复。

这些要求是本训练的作业规则，不是 CPython 官方 core developer 准入标准。学习旧版本之外，还需要逐步参与现代代码库的贡献、评审与维护。

## 作业顺序

1. [给 list 增加 extend 和 pop 方法](01-list-methods.md)
2. [添加 assert 语句](02-assert-statement.md)（已通过评审，见 [评审记录](02-assert-statement.review.md)）
3. [实现 `**` 幂运算符](03-power-operator.md)
4. [给字符串对象加方法支持](04-string-methods.md)
5. [新增 `list()` 与 `dict()` 内建构造器](05-container-builtins.md)
6. [实现增强赋值（`+=` 等）](06-augmented-assignment.md)

一次只做一道题，上一题通过评审后再开始下一题。第一题现在可以开始。

## 每题交付

- 实现和自动化测试。
- 简短设计说明：行为、改动位置、引用所有权和错误处理。
- 实际运行命令及结果。
- 一个独立 commit，不混入生成的构建产物、Demo 大小写冲突或无关整理。

失败测试必须让测试进程以非零状态退出，不能仅打印失败信息。遇到已有历史问题，先记录基线，再区分是否由本次改动引入。

提交评审时说明“请严格 review 第 N 题”，附上 commit 和验证命令。评审会包含独立检查、额外测试和设计追问；自己编写的测试通过，不代表作业自动通过。

可以申请分级提示。如果关键实现由评审者完成，需要换一个变体重新独立完成。

## 评审标准

| 项目 | 分值 |
| --- | ---: |
| 行为和边界正确 | 40 |
| 错误路径、引用与状态恢复 | 25 |
| 测试能发现真实错误 | 20 |
| 改动范围和设计解释 | 15 |

达到 85 分且没有阻塞问题才通过。崩溃、引用错误、异常被吞掉、测试假成功，任何一项都阻塞通过，不能用其他分数抵消。
