# 第六题：实现增强赋值（`+=` 等）

在 `test/1d5735e8462` 分支完成。共同交付要求和评审标准见 [README](README.md)。第五题通过评审后再开始。

## 目标

当前 `x += 1` 是语法错误。实现增强赋值：`+= -= *= /= %= **= <<= >>= &= |= ^=`，
作用于 name、属性（`a.b`）、下标（`a[i]`）三类目标。

训练重点：语法产生式、赋值目标处理（`com_assign` 系列）、操作数栈管理、副作用只发生一次。

## 语义规定

- `t op= v` 的语义是：目标 `t` 只求值一次；读取其当前值，与 `v` 做 `op`，写回 `t`。
- 复杂目标只求值一次：`a[f()] += 1` 中 `f()` 只调用一次，下标对象也只求值一次。
- `a.b += v`、`a[i] += v` 的目标表达式（`a`、`i`）各只求值一次。
- 与普通赋值一样是语句，没有表达式值。
- 错误路径：读取、运算、写回任一步抛异常时原异常传播，且不重复执行目标副作用。
- `**=` 的语义依赖第三题；若该题尚未完成，请把 `**=` 排除或标注为可选，并说明范围。

## 涉及层次

- `Python/compile.c`：实现代码生成，复用现有目标处理逻辑（注意别把复杂目标重复求值）。
- 用 pgen 重新生成 `Python/graminit.c`、`Include/graminit.h`。

## 实现约束

- 不得改变普通赋值（`=`）的行为与优先级。

## 验收要求

1. 对 name、属性、下标三类目标，`+=` 等结果正确。
2. 副作用只发生一次的检查：`a[f()] += 1` 中 `f()` 调用次数为 1。
3. 每个运算符的结果与 `t = t op v` 一致。
4. 错误路径：目标读取或写回失败时原异常传播，不重复副作用。
5. 普通赋值与其它语句行为不回归。

## 测试要求
